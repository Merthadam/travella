# Three onboarding directions — throwaway prototype

Question: which interaction/layout makes Travella's four-step preference onboarding engaging and clear?

Build three structurally different React variants in the existing frontend prototype folder, gated behind a development-only onboarding preview query. Use the current Travella brand and typography. A: centered journey with passport wallet; B: split-screen live travel profile; C: compact boarding-pass form with a horizontal journey strip.

All variants: top progress, required home city, optional airport choice from mocked nearby suggestions, optional multi-citizenship wallet, two free-text needs fields, at least five interests including custom entries OR skip the whole interest step. Back navigation preserves in-memory edits. No real maps, agents, account access or persistence; clearly label simulation. Switch variants by URL and floating controls, preserve state, expose state in a reviewer panel. Accessible keyboard targets and reduced-motion behavior.

Serve with one npm prototype command on a confirmed free localhost port. Inspect all variants with Chrome DevTools; capture screenshots if the tool permits. No automated tests or paid API calls. Save this work on the dedicated prototype branch and await user selection before production implementation.
