# Plan: implement the single-purpose traveler intake node

## Goal

Add a reusable LangGraph intake node that asks one focused traveler-preference question at a time, clarifies ambiguous answers, and returns answer candidates. The node has no tools, profile reads, persistence, search, or confirmation side effects.

## Task 1 — Build the isolated LangGraph intake unit

- Add a typed intake state and a single-node LangGraph builder.
- Use the existing model adapter to generate a short question/clarification and structured answer candidates from traveler-provided messages only.
- Keep the intake schema limited to candidate topics already discussed: departure city/airport, citizenship, food/allergy needs, accessibility, and optional interests. Do not require a complete checklist or infer missing values.
- Do not register or call any search, profile, CRUD, memory, or other tools from this node.
- Add focused tests for opening prompt behavior, one-question limit, clarification, explicit answer extraction, skip/finish, and no tool or persistence calls.
