# Redesign account access, preserve functionality

User requested redesign of the unattractive login screen with existing functionality. Offered prototypes or direct redesign; no response during review and baseline capture, so defaulting to lightweight prototype exploration consistent with the preceding header workflow. No production design selected yet.

Three development-only variants on existing `/` route with `?prototype=account-access&variant=A`: split welcome, quiet centered form, workspace-style layout. Preserve available journeys in simulated UI: email/password sign-in, registration (name/email/password), email verification/resend, recovery/reset, MFA/recovery and success/error/busy states. Real authentication remains unchanged. No social sign-in or new authentication capability.

Use existing palette/font foundations, clear field labels, strong primary action and less prominent secondary actions. Desktop/mobile/light/dark. Shared floating variant controls with arrow-key switching and URL persistence. Prototype submissions stubbed and clearly labelled; no credentials or codes persisted or transmitted.

Verify each variant with Chrome DevTools, exercise simulated navigation/states, capture and inspect screenshots. Source retained on a throwaway prototype branch. User selection is required before promoting a design to production. Existing authentication handlers and session/security behavior must be retained in subsequent implementation.
