# Integrate AgentCore Memory with traveler profiles and Plan context

## Goal
Wire the accepted traveler profile through AgentCore Memory without expanding the onboarding intake node. CRUD remains canonical; AgentCore is advisory, traveler-scoped memory. Plan turns may use the scoped preference context, but current Plan instructions remain authoritative.

## Tasks
1. Inspect the current auth/profile and Plan context boundaries; implement an AgentCore Memory adapter with safe disabled behavior and explicit configuration.
2. Sync only the successful CRUD profile snapshot from the authenticated auth boundary to AgentCore; expose non-sensitive sync status and retry via profile save.
3. Retrieve scoped profile memory for Plan context only, keeping onboarding intake stateless and preventing raw identifiers from namespaces/logs.
4. Add focused adapter/API/service coverage and record verification evidence. Do not write personal data to the live AWS resource; use stubs/local HTTP tests.
5. Update quick task summary and project quick-task state.

## Acceptance
- AgentCore is called only when configured and after canonical CRUD save succeeds.
- Memory writes use token-verified traveler subject-derived namespace and no email/address.
- AgentCore outages do not undo saved CRUD profile; clients can see memory sync status.
- AgentCore context is added to Plan turns outside onboarding and treated as advisory.
- Tests verify API projection/identity boundaries, disabled mode, and failure behavior.
