# Default local Cognito startup

## Goal

Make the documented default local startup configure and validate the existing Travella Cognito setup before Docker starts, so authenticated browser checks are ready by default.

## Tasks

1. Update `.agents/skills/travella-local/SKILL.md` with safe AWS CLI steps using the existing `default` profile and configured region to discover the uniquely named local user pool and its expected app client, validate the client supports password authentication without a client secret, and derive the pool ID, client ID, issuer, and JWKS URL into the local app configuration before invoking Compose. Require unambiguous discovery and fail with a sanitized, actionable message when AWS credentials, region, pool, or client are missing or ambiguous. Never print credentials, account details, or secret values. Keep the existing example-account check after startup. State that Cognito setup cannot bypass an app migration failure (including a missing migration revision), and troubleshooting must preserve the PostgreSQL volume.

## Boundaries

- Use the existing AWS `default` profile and the established local region; do not create or modify Cognito resources or change account credentials.
- Do not include pool/client identifiers, account email, or password in the skill or plan.
- Do not delete or recreate the local database volume. A Docker app migration failure remains a separate startup blocker even after Cognito configuration succeeds.

- Confirm the skill retains the authenticated example-account check and documents migration failure as independent from Cognito configuration.
- Documentation-only change: no application/browser run is required by `docs/skills/travella-testing/SKILL.md`.
