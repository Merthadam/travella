# Local-only MCP adapter path

## Goal

Run Travella research and map tools locally through their real FastMCP Streamable HTTP endpoints, without provisioning or calling AgentCore Gateway. Keep the existing Cognito authentication, active Plan ownership check, MCP service credential verification, and short-lived Plan assertion contract. This is a development transport only; production remains on AgentCore Gateway.

## User journey and acceptance criteria

An authenticated traveler asks the agent to research a theme. LangGraph chooses research, calls the local research MCP server, resolves candidate locations through the local map MCP server, and returns bounded candidate projections. Research never changes durable Plan state.

- Local mode works with no `AGENTCORE_GATEWAY_URL` and reports its selected transport in health without exposing secrets.
- Calls use the real MCP protocol and the existing authenticated MCP ASGI endpoints.
- The local adapter creates a short-lived service JWT and Plan-scoped assertion only after the agent has validated the Cognito identity and active Plan.
- Unauthenticated, wrong-Plan, invalid-service-token, and expired-assertion requests remain rejected by the MCP servers.
- Development/test defaults to local MCP; production remains on AgentCore unless explicitly reconfigured.
- Tavily and Google server keys are injected only into MCP target containers, never the browser or agent container.
- Both the normal and combined-app local Compose configurations start the two MCP services; no AWS AgentCore resources are required.
- The local combined app defaults to the configured OpenAI model provider and keeps Cognito on its existing user pool; no AgentCore Gateway or Memory calls are made.

## Tasks

1. Add a development-only local MCP adapter using the official MCP Streamable HTTP client. Route research/source calls to the research server and map calls to the map server. Sign the same service JWT and scope assertion that the current target middleware verifies. Keep the AgentCore adapter as the production default and add focused adapter/security tests.
2. Add both FastMCP targets to the two local Compose configurations. Create a persistent, git-ignored local auth-secret file on local startup, pass only those auth secrets to the agent and MCP targets, and keep the provider-key env file on the MCP targets. Update local setup docs and non-secret health output.
3. Run the agent/MCP/auth regression tests, exercise local MCP protocol and denial paths, validate both Compose files, run the repository check, and save the executed results in `artifacts/testing/2026-10-03-local-mcp-without-agentcore/verification.md`.

## Scope boundaries

- No AgentCore Gateway, Runtime, or Memory provisioning.
- No frontend changes or CRUD endpoint changes.
- Local means the Travella app, agent orchestration, and MCP tool servers run in local containers. The model, Tavily search, Google geocoding, and Cognito user pool remain server-side external integrations; do not claim offline operation.
- Long-term agent memory is not enabled by this task. PostgreSQL-backed local memory is a separate follow-up decision; CRUD data and Cognito session data remain on local PostgreSQL.
- Do not read or print either ignored `.env` file; Compose may load the MCP provider-key file into the MCP target services.
- Existing dirty worktree changes are user/session state. Do not revert, stage, or commit unrelated files.
