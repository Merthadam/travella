# Plan 11-03: Runtime credentials, evaluation, and safe rollout

## Objective

Ensure the worker can run locally and in AgentCore Runtime, validate real deployment behavior, and preserve safe rollback.

## Tasks

Decision coverage: D-12: fetch the Anthropic key from AWS Secrets Manager without exposing it; D-13: leave other model calls on their configured provider.

1. Trace the actual local and production secret-loading paths. Add explicit `ANTHROPIC_API_KEY` secret configuration and least-privilege runtime retrieval only where absent; do not assume local secret sync automatically configures the AgentCore Runtime role.
2. Keep secret values out of `health`, logs, errors, image layers, and environment diagnostics. Validate missing/invalid key handling without live provider calls.
3. Build the AgentCore Linux/ARM64 image and confirm SDK CLI startup, network requirements, stop/cancel process cleanup, and graceful shutdown. Keep the existing graph/runtime contract and candidate tools.
4. Extend Phase 10's labeled eval set to cover the rubric in `11-AI-SPEC.md`; use mock tools in CI and a separate explicitly enabled live-provider smoke case.
5. Update the runbook with IAM scope, secret ARN, required env/config values, model/cost limits, build validation, canary steps, and rollback to the prior research adapter.
6. Verify end-to-end streaming still emits only supported answer text and cited sources, while keeping the current frontend unchanged.

## Verification

- `uv run pytest -q services/agent/tests services/agent/evals`
- `uv run ruff check services/agent`
- `docker buildx build --platform linux/arm64 -f Dockerfile.agent-runtime --load -t travella-agent-runtime:phase11 .`
- With deployment credentials and provider configured, run the documented authenticated Runtime smoke path and confirm one factual research turn, one candidate-discovery turn, cancellation, and sanitized logs.
