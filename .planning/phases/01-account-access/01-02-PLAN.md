## Must-haves

### Truths

- D-01: Registration, verification, sign-in, and recovery use one guided stepper.
- D-02: The stepper displays an explicit named checklist of auth steps.
- D-03: Registration collects first name, last name, email, and password before the dedicated email-verification step.
- D-04: Recovery is the dedicated email → neutral confirmation → reset link → new password → sign-in path.
- D-06: Back navigation preserves safe non-secret values but never passwords or verification codes.
- D-07: Each step uses an error summary plus inline field errors while retaining safe values.
- D-08: Interruption restores only non-secret progress and requires passwords/codes again.
- D-09: The visual treatment is calm and focused with one primary action per step.
- D-10: The first implementation is desktop-first with a simpler small-screen fallback.
- D-11: Each step offers Back plus a primary action and cannot skip required security.
- D-12: Registration and recovery success use a confirmation screen with explanation and Continue.
- D-13: Optional authenticator-app MFA is offered after email verification and before first private access.
- D-14: Recovery codes have a dedicated review with copy/download and acknowledgement, are shown once, and are never emailed.
- D-15: Recovery-code sign-in requires authenticator replacement before My plans.
- D-16: Recovery-code replacement re-authenticates or completes MFA, invalidates the old set immediately, and shows the new set once for acknowledgement.
- D-21: Invalid sign-in uses the generic actionable message “We couldn’t sign you in. Check your details or reset your password.”
- D-22: Password recovery explains neutrally that instructions are sent if the address is eligible and what to do if none arrives.
- D-23: Expired/used links explain the problem and offer resend/recovery without account disclosure.
- A new traveler cannot access private routes until email verification succeeds.
- Recovery responses are neutral for unknown, unverified, and eligible addresses.
- MFA recovery codes are one-time, shown once, never emailed, and replacement invalidates the old set.
- Password reset never creates a session and never bypasses configured MFA.

## Threat model

- Account enumeration is mitigated by neutral recovery and generic sign-in errors.
- Secret persistence is prevented through explicit state-machine field classification and reload tests.
- Recovery-code replay is prevented by one-time consumption and replacement invalidation.
