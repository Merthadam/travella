## Goal

Create the smallest production-shaped identity boundary: validated Cognito access-token claims, token-derived ownership, a 30-day Travella session policy, and safe internal return handling.

## Must-haves

### Truths

- Every public service validates the access token independently before private-resource access.
- Authorization uses the validated token subject and never a browser-supplied traveler ID.
- Silent refresh cannot continue beyond 30 days from full sign-in.
- Failed refresh clears private state and preserves only a safe internal return destination.

### Artifacts this phase produces

- `src/auth/contracts.ts`
- `src/auth/token-validator.ts`
- `src/auth/session-policy.ts`
- `src/public-api/auth-middleware.ts`
- `ValidatedIdentity`, `AuthProblem`, `canRefresh`, `sanitizeInternalReturn`

## Threat model

- Token confusion, algorithm/key substitution, expired tokens, wrong audience, and missing scopes are blocked before handler execution.
- Owner spoofing is blocked by deriving identity from the validated `sub` claim.
- Open redirects and secret leakage are blocked by internal return-path sanitization.
