<interfaces>
Reuse AccountOutput and /auth/account/verification purpose-bound proofs from 13-03. All account operation routes require current_session and existing CSRF/body/rate protections.

POST /auth/account/password: {current_password:SecretStr,new_password:SecretStr,verification_id,event_id:UUID}; 200 {state:complete,account:AccountOutput} after ChangePassword acknowledged. Confirm password is browser-only. A recorded event is never executed twice; retries return its recorded safe state rather than submitting passwords again. No password or password-derived digest is persisted in operation records.

POST /auth/account/authenticator/start: {mode:setup|replace,verification_id,event_id:UUID}; {state:enrollment_required,operation_id,secret_code,expires_in:300}. secret_code is a dedicated transient response only. Proof purpose must match mode; setup requires off, replacement requires on. POST /auth/account/authenticator/verify: {operation_id,code:SecretStr}; {state:complete,account:AccountOutput}. POST /auth/account/authenticator/disable: {verification_id,event_id:UUID}; {state:complete,account:AccountOutput}. Disable is allowed only by capability and fresh purpose-bound proof; it disables preference, not deletion of the registered secret.

POST /auth/account/recovery-codes/rotate: {verification_id,event_id:UUID}; {state:codes_generated,codes:string[],account:AccountOutput}. Require active authenticator and recovery_rotate proof. Generate 10 codes with at least 128 bits each (secrets.token_hex(16).upper fits existing input bound); store only existing digest format in encrypted recovery payload. Repeat event never generates another set or re-discloses plaintext: return 409 disclosure_unavailable with safe account/count. Existing legacy code validation remains accepted.

POST /auth/account/operation-status accepts {event_id:UUID} and returns {state:not_found|pending|complete|result_unknown,account:AccountOutput}; subject/session bound and read-only despite POST. No raw input, codes or enrollment secrets. Use this on ambiguous responses; status cannot prove whether an unacknowledged ChangePassword happened, so result_unknown remains honest until the user checks access or explicitly begins a fresh operation. Never automatically retry password, replacement or code rotation.

AccountSecurity receives setting, account, onAccountSaved, onExpired and the page's dirty/secret-exit guard callbacks. It owns transient sensitive forms/disclosure and consumes the same request helper. No ordinary profile mutation from any security editor.
