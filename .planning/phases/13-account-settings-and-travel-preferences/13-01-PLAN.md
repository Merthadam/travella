<interfaces>
Existing request(path, body, {method}) sends same-origin cookies, no-store and X-Travella-Request and throws ApiError with status/code/fields. Existing readTravelerProfile() returns ProfileOutput. Use it directly; a second fetch client is unnecessary.

New PATCH /v1/traveler-profile/sections accepts exactly {section, values, expected_revision, event_id}. section is home|citizenship|needs|interests; expected_revision is a strict nonnegative integer; event_id is a UUID. This plan enables needs only; the remaining supported section validators/writers become reachable in 13-02. needs values are exactly {food_needs: string, accessibility_needs: string}, each bounded at 1000 with existing normalization. A request for a section not yet implemented returns invalid_profile rather than succeeding.

Success 200 returns the existing complete ProfileOutput (including revision, updated_at, exists, onboarding and onboarding_complete); auth may append existing memory_sync. No receipts or identity fields in this response. Invalid section/values: 422 invalid_profile; stale revision: 409 revision_conflict; reused event with changed normalized payload: 409 request_reused. Auth 401 means session expiry; network/provider 5xx must preserve ordinary drafts.

AccountSettingsPage receives onExpired, onNavigatePlans and initialProfile; it owns one active setting and its draft. Subsequent plans extend this page with actual preference/identity/security setting components. Keep setting identifiers constant: name, email, home, citizenship, needs, interests, password, authenticator, recovery. /account contains no private values. Default selection becomes home when 13-02 makes it editable; until then the working needs path is the initial active setting. Do not display invented identity or successful unavailable operations.
