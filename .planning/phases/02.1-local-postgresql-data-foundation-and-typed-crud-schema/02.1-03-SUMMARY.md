# Phase 02.1 Plan 03: PostgreSQL-backed encrypted auth state Summary

Auth sessions, recovery-code sets, and MFA enrollment state now use SQLAlchemy Core against the shared migration-owned database. Fernet ciphertext and opaque cookie digests remain the storage boundary; timestamp inputs are converted to UTC-aware values and auth operations share an explicit transaction connection. PostgreSQL recovery-code consumption locks the owning row so one-use semantics hold across workers.
