# Phase 02.1 Context — Local PostgreSQL data foundation and typed CRUD schema

Date: 2026-09-29

## Domain

Replace the local SQLite persistence boundary with PostgreSQL and define the durable types needed by CRUD and the upcoming agent flow.

## Decisions

- PostgreSQL is the only local Compose database for Plans and auth sessions; SQLite fallback is removed from the runnable local stack.
- Structured payloads use PostgreSQL JSONB, especially planning briefs, agent event projections, and evidence metadata.
- Alembic migrations are the schema authority. Startup must fail when the database is not migrated rather than silently creating or altering tables.
- CRUD remains the only owner of durable Plan, destination, brief, and lifecycle state.
- UUID identifiers remain the public identifier type; timestamps are timezone-aware UTC values.
- Lifecycle and receipt statuses remain constrained enums; latitude and longitude remain bounded numeric values; provider IDs and external references remain bounded strings.
- Local verification uses an isolated PostgreSQL test database and exercises the HTTP CRUD handlers for create, read, update, delete/restore, ownership, and invalid input.

## Scope boundaries

- This phase does not provision production RDS/Aurora.
- This phase does not move AgentCore Memory or MCP evidence into PostgreSQL.
- This phase does not add frontend behavior.

## Verification targets

- Compose starts PostgreSQL and CRUD connects through `CRUD_DATABASE_URL`.
- Alembic applies the schema cleanly and refuses an unmigrated database at startup.
- CRUD HTTP integration tests verify persistence and ownership against PostgreSQL.
- JSONB values round-trip without string encoding and enum/UUID/timestamp constraints remain enforced.
