# Plan 04: Purge, boundary, and release verification

## Objective

Close the lifecycle's retention and security risks with deterministic purge execution, cross-service negative tests, and a reproducible local release check that proves no deleted data or credentials escape the boundary.

## Artifacts this phase produces

- `services/crud/purge.py`: idempotent eligible-plan purge command/service method.
- CRUD/auth boundary and purge/security test modules.
- `README.md` and `scripts/check.sh` lifecycle verification documentation/wiring.
