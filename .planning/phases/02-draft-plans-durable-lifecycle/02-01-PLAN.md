# Plan 01: Durable Plan model and transactional repository

## Objective

Create the CRUD-owned durable model and repository that can atomically create a Draft Plan plus Conversation, maintain title provenance/activity/resume state, soft-delete and restore within seven days, and purge identifiable data safely. This is the tracer slice for durable lifecycle behavior and does not expose an HTTP route yet.

## Artifacts this phase produces

- `services/crud/models.py`: `Plan`, `Conversation`, `PlanActionReceipt`, `PlanChallenge` SQLAlchemy models and lifecycle enums.
- `services/crud/contracts.py`: typed PlanRef, ConversationRef, Problem, mutation/result and projection schemas.
- `services/crud/repository.py`: transactional create/list/open/activity/rename/delete/restore/purge methods, request receipt and challenge consumption helpers.
- `services/crud/migrations/versions/0001_plan_lifecycle.py`: initial schema migration.
- `services/crud/config.py`: CRUD database/session configuration.

<threat_model>
- T02-01 high: IDOR/foreign Plan access — mitigate with verified traveler subject predicates on every repository query and indistinguishable safe not-found responses.
- T02-02 high: replay or double mutation — mitigate with time-bound request IDs, exact payload digests, row locks, atomic challenge consumption, and receipts in the same transaction.
- T02-03 high: deleted data resurrection or retention leak — mitigate with lifecycle checks before receipt replay, cascade purge, no identifiable purge audit rows, and no browser/private payload in receipts.
- T02-04 medium: title/content injection — mitigate NFC normalization, control-character rejection, escaped projections, and no HTML/Markdown title interpretation.
</threat_model>

## must_haves

### truths

- [D-01][D-03] Plan and Conversation creation is one atomic transaction and one idempotent result.
- [D-02][D-04][D-07] Every durable mutation is traveler-scoped, revision-checked, exact-payload-bound, and replay-safe.
- [D-05][D-09] Explicit activity is separate from read-only GET and determines most-recent ordering.
- [D-06][D-08] Soft delete, restore, seven-day eligibility, and irreversible identifiable-data purge are represented in durable state.
- [D-10] Automatic title proposals are represented as exact confirmed values without weakening manual title provenance.
