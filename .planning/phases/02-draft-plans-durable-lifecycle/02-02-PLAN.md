# Plan 02: Authorized CRUD API and session integration

## Objective

Expose the documented Plan lifecycle through a deny-by-default CRUD API and connect the existing opaque-cookie auth boundary without exposing Cognito credentials or trusting browser identity.

## Artifacts this phase produces

- `services/crud/app.py`, `services/crud/api.py`, `services/crud/auth.py`: CRUD FastAPI application, routes, verifier dependencies, and allow-listed projections.
- `services/auth/crud_client.py`: server-side allow-listed client that forwards the current verified access token to CRUD.
- `compose.yaml` CRUD service definition and check-script coverage.

<threat_model>
- T02-05 high: token confusion or browser identity spoofing — mitigate with independent CRUD Cognito validation, server-held token forwarding, and subject-derived queries only.
- T02-06 high: projection/log leakage — mitigate with explicit response schemas, header allow-listing, no-store responses, and tests asserting absence of credentials, email, raw payload, and reasoning.
- T02-07 medium: unsafe mutation retries — mitigate with mandatory request ID/revision/challenge headers and stable Problem responses.
</threat_model>
